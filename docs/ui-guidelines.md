# UI 実装ガイドライン

本ドキュメントは /docs/requirements.md を補完し、画面ごとの UI 仕様・ユーザーからの追加要望を整理する。

## 起動時の表示
- 保存データの初期化中は、iOSの起動画面で現行ロゴを200pt四方・画面全体の中央に表示する。背景はライトで完全な白（#FFFFFF）、ダークで完全な黒（#000000）とし、アプリ内の起動アニメーションも同じ色・位置・大きさに揃える。起動専用ロゴは背景透明のベクターとし、AppIconのPNGに含まれる背景の色ムラや四角い境界を表示しない。
- iOS標準の静止起動画面は、ロゴ背面の不透明な`LaunchBackdrop`画像（ライト白／ダーク黒）を画面全体に敷く。背景色アセットの解決に依存せず、セーフエリア外も含むroot viewの四辺へ画像を固定してSwiftUI側との明暗差を避ける。
- 最初の画面の準備後、青い丸だけを下端固定で少し潰して溜める（0.07秒）。縦に伸びながら勢いよく跳び（0.025秒）、28pt上方の頂点で減速して丸に戻る（0.045秒）。加速しながら元の位置へ落ち（0.055秒）、着地で少し潰れ（0.025秒）、丸に戻る（0.03秒）。予備動作・イージング・スクワッシュ＆ストレッチで重さと弾力を表す。
- 着地して形が戻った丸の内側を透明にして背後のホーム、またはロック解除画面を見せ、その丸の中心を固定したまま円形の窓を画面全体へ広げる（0.28秒）。窓に細い青い縁と淡い影を付け、拡大終盤で縁と影を消す。マスクと縁は同じ補間値で動かし、窓の外側は起動背景とロゴで覆う。指定時間の合計は約0.53秒（フレーム描画・段階の完了処理で実時間は前後する）とし、ロゴのための待機時間や通信完了待ちは追加しない。
- アニメーションは起動時に一度だけ表示し、バックグラウンドからの復帰では繰り返さない。初回案内やウィジェットからの画面表示は完了後に処理する。
- iOSの「視差効果を減らす」が有効な場合は、拡大や跳ねを行わず0.1秒のフェードだけで切り替える。ロゴ内に説明文やアプリ名は追加しない。

## 下部タブ
- タブを ホーム / カレンダー / 買い物 / 習慣 / ヘルス の順に配置する。
- 買い物タブの短いラベルは「買い物」、画面タイトルは「買い物リスト」、タブアイコンはカートの SF Symbol とする。

## Today (ホーム)
- ヘッダーは日付(YYYY / MM/DD) + 天気(最高ミニマム/最低温度)を1行または2行でコンパクトに表示。文字サイズを大きくし視認性を高める。
- カレンダー予定: 色付きカード + タイムライン (カレンダー画面と同じ `TimelineItem`)。イベントはタップで編集シート。
- タスクセクション: 今日が期限のタスクのみ表示し、他日タスクを追加するには「タスクリスト」へ誘導。
- タイムライン表示: 6:00~24:00、イベント/タスクをブロック表示し注釈を入れる。
- 習慣: アイコン・カラーを付け、タップで完了トグル。
- 習慣行は1行で、固定幅のアイコン、左寄せの習慣名、名前の右側の連続日数、右端のチェックを並べる。連続日数の表示・非表示や桁数の変化でも名前の左端とチェックの位置を保つ。長い名前は1行で末尾を省略する。
- 連続日数は炎のアイコンと短い日数表記（例: 14日）で示し、0日のバッジは表示しない。習慣タブと同じ予定日単位の連続達成数を使い、表示日が予定日で未完了なら0とする。VoiceOverでは習慣名・完了状態・連続日数を読み上げる。
- ヘルス: 歩数棒グラフ (値ラベル付き)、睡眠タイムラインの概要、ステップ/スリープの相関チャート。
- **FAB (Floating Action Button)**: 画面右下に常駐。「＋」アイコン。タップで「タスクを追加」「予定を追加」メニューを展開。
- **ツールバー (右上)**: 以下の3つを配置し、Today / Calendar で統一する。
  - [メモ]: 共通メモエディタを開く
  - [リスト]: 予定リスト / タスクリスト の選択メニュー
  - [設定]: アプリ設定画面を開く

## カレンダー
- 表示モード: 週/月切替 (segmented control)。
- 月表示: カレンダーを数字表記 (月名を英語ではなく数字)。今日の枠は淡い背景。ダブルタップ案内を必ず記載。
- 週表示: 上部に週カレンダー、下に週タイムライン。時間軸と予定ブロックがズレないよう `TodayAxisView` / `TimelineColumnView` で統一。  
  - タイムライン下に日詳細 (タスク/習慣/日記/ヘルス) を月表示と同じコンポーネントで表示。  
  - 日付ダブルタップで追加できることを文言で案内。  
  - 予定/タスクともに編集シートあり。  
  - 表示重なりを避けるためカラム幅や blockHeight を調整。  
  - 今日以外の日にいる場合のみ「今日へ」ボタン表示。
- 週/ 月ヘッダー: 左右スワイプ (ボタン) で移動、週移動は 7 日単位。
- **FAB / ツールバー**: Todayと同様に右下にFAB、右上に統一ツールバー (メモ/リスト/設定) を配置する。

## 買い物リスト
- 標準の `NavigationStack` / `List` / `Form` / シートを中心に、HIG に沿った純正アプリらしい UI にする。商品イラストや装飾画像は置かず、チェックや追加などの操作に SF Symbols を使う。
- 一覧上部に「すべて」「未指定」と登録済み購入先の選択を置く。特定の購入先を選択中に商品を追加すると、その購入先を初期選択する。「すべて」では購入先ごとに商品をまとめる。
- 一覧の「商品を追加」から、標準の大きなシートで専用の追加画面を開く。上部に「閉じる」を置き、見出しと件数は「今回追加した商品（件数）」の1行にまとめる。入力中は今回追加した商品の商品名・購入先・メモを見やすい一覧に表示する。追加が成功したらすぐに新しい行を表示し、各行の「取り消す」でその追加を削除できる。「閉じる」で購入先ごとにまとめた通常の一覧へ戻る。追加済みの商品は閉じても保持する。
- 商品追加は商品名だけを必須とし、購入先は任意。商品名入力の横に「＋メモ」を置き、標準の複数行の「メモ（任意）」入力欄を同じ画面内に表示する。メモ用の別シートやキーボードツールバーは使わない。数量は独立した項目として表示・編集せず、個数やグラム数などもメモに自由に記載する。メモは後から編集できる。旧データの数量は既存のメモを失わずにメモへ移し、一覧と編集画面のメモに表示する。
- 追加ボタンと商品名入力の Return のどちらでも、保存成功時だけ商品名とメモを空にしてメモ欄を閉じ、キーボードと商品名の入力位置を維持して次の商品を入力できる。商品名とメモは同じネイティブ入力のフォーカス管理で切り替え、商品名へフォーカスを移してからメモ欄を閉じる。SwiftUI のフォーカス解除でキーボード全体を閉じない。保存に失敗した場合は商品名・メモとメモ欄の表示を保持する。選択した購入先は連続追加で保持する。
- 専用の商品追加画面では購入先を横並びの選択肢として常時表示し、必要に応じて横スクロールできる。選択状態を色と読み上げで伝える。購入先と商品名の入力部分はタップ領域を保ちながらコンパクトにする。商品名入力は丸みのあるカプセル形に整え、丸い SF Symbol の「＋」ボタンを隣に置く。システムの配色・文字サイズに合わせる。入力欄をキーボード直上に置き、別の「入力を完了」キーボードツールバーや余分な隙間を作らない。
- 「未指定」の長押しメニューに「非表示」を用意し、購入先の管理画面に「未指定を表示」のスイッチを置く。「非表示にしても商品は削除されません。」と説明する。設定は一覧上部と専用の商品追加画面の両方に適用し、「すべて」にある未指定の商品は残す。追加時の購入先が未指定なら、非表示時は登録済み購入先の先頭に切り替える。
- 一覧にはこれから買う商品だけを表示し、購入済みの一覧や購入履歴、頻度による並べ替え、再購入の操作は置かない。商品行全体を購入チェックのタップ領域とし、商品名・メモ部分も同じ動作に揃える。習慣画面と共通のアニメーション付きチェックボックスを再利用する。編集・削除などは行の独立したメニューから行い、メニュー操作で購入チェックしない。チェック後は約350ミリ秒のアニメーションを見せてから行を消す。
- 購入チェック時は画面下部に「商品名を購入しました」と「元に戻す」を6秒間重ねて表示する。一覧と「商品を追加」ボタンを押し上げない。続けてチェックした場合は最後にチェックした商品へ更新し、6秒の表示期限を延長する。「元に戻す」は同じ商品のID・商品名・メモ・購入先・作成日を保って復元する。チェック時に商品を端末内の保存データから即時削除し、取り消し用の内容は表示中だけメモリに保持する。表示期限後・画面遷移後・再起動後には残さず、次に必要な商品は商品追加画面から入力する。
- 商品を編集・削除できる。購入先の管理画面では追加・名前変更・削除・標準の並べ替え操作を提供する。購入先の削除時は確認を表示し、商品を「未指定」に移して保持する。
- オフラインでも追加・チェック・自動保存を行い、未購入は翌日以降も残す。保存に失敗した場合は保存できていないことを利用者に伝える。
- システムの文字サイズ・配色・VoiceOver に対応し、チェック状態と購入先フィルタの選択状態を読み上げ可能にする。
- UI 文言は5言語で完備し、商品名・購入先名・メモなど利用者の入力はそのまま表示する。

## 予定ウィジェット（中サイズ）
- 左に今日の日付・予定・未完了タスク、細い区切り線を挟んで右に当月のミニカレンダーを配置する。
- 左の一覧は最大5件。高さが足りない場合は件数を減らし、表示しきれない予定・タスクの件数を最下部に示す。
- ミニカレンダーは曜日・日付で構成する。当月は左上の日付で分かるため右側の月名を省き、曜日行を左の日付と揃え、残りの高さを週数に応じて均等に配分する。今日をアクセント色の丸で強調し、予定がある日の下に点を付け、土日は控えめに色分けする。
- 曜日・日付の表記は端末の言語・地域・カレンダー設定に従う。週の開始曜日はアプリ設定の「週の始まり」（日曜 / 月曜、初期値は日曜）に従い、アプリ内の月・週・振り返り表示、予定ウィジェット、壁紙カレンダーで揃える。4〜6週の月に対応し、月外の日付は空欄にする。
- 日をまたぐ予定は各該当日に点を付ける。終了時刻が午前0時なら終了日は含めない。タスクは左の一覧に表示する。
- 各日付のタップでアプリの該当日の予定詳細を開く。VoiceOverでは日付・今日・予定の有無を読み上げる。

## 設定 (Settings)
- 構成:
  - **カレンダー**: 週の始まり / 「予定のカテゴリ」(名前・色の管理) / 「カレンダー連携」(外部カレンダーの表示先設定) / ロック画面カレンダー
  - **プライバシー**: 「アプリロック」トグル (ONでFace ID/パスコード有効化)
  - **ヘルスケア**: 設定アプリへの誘導ボタン + 手順テキスト
  - **サポート**: 「応援する」(レビュー) / 「不具合報告」(メーラー起動)
- モーダルまたはナビゲーション遷移で表示。
- カレンダー連携は「表示するカレンダー」「表示しないカレンダー」のセクションに分ける。各行はiOS側の色を使うカレンダーアイコン、カレンダー名、明示的な「表示先」とカテゴリ色・カテゴリ名を示す。予定の色は表示先カテゴリに従い、同じカテゴリを使う予定の色が一緒に変わることを説明する。
- カテゴリ選択画面は色・名前・選択印を示し、行のタップで選択する。「カテゴリを管理」から設定と共通の管理画面へ進む。管理画面では行のタップで編集し、名前・色と削除操作を示す。色は44pt以上のボタンと選択印で選べる。削除時は予定を残すことと移動先を確認する。
- 編集をキャンセルした場合やカテゴリ選択を閉じるだけでは変更せず、色の保存は一覧と予定表示にすぐ反映する。連携の未許可時は許可操作、アクセス不可時は設定への導線、0件時はカレンダー追加の案内を表示する。

### ロック画面カレンダー
- この機能を端末で初めて開いたときだけ、小さな「ようこそ」と目的を伝える見出し「ロック画面で、予定をひと目に」の画面から案内を自動表示する。初回表示済みを端末内に記録し、途中で閉じた場合も次回は通常の設定ページを表示する。「設定手順をもう一度見る」も「ようこそ」から開く。
- 「ようこそ → 1. 壁紙を作る → 2. ショートカットを追加 → 3. 自動更新を設定 → 完了」の順とし、1画面につき1つの目的に絞る。全体のステップ番号と、その中のページ番号を区別する。
- ステップ1は「背景を選ぶ」「レイアウト・表示する週数を決める」「表示する情報を決める」「完成した壁紙を確認する」の4画面に分ける。背景画面には写真／色の見本と選択操作を置き、写真の位置や拡大率の調整は別シートで開く。レイアウトとプライバシーは、それぞれの画面に専用の設定カードを置く。完成プレビューは独立した画面に幅210ptの端末表示として置き、「この壁紙でよろしいですか？」と確認してから次へ進む。
- ステップ2は「ショートカットを使う理由」「追加」「動作確認」の3画面に分ける。理由の画面で、lifelify が画像を作り、Apple のショートカットが壁紙に反映する役割を説明する。追加・確認の画面では、リンクを開く、追加を押す、lifelify に戻る、追加したショートカットを実行する、ロック画面を確認する流れを具体的に示す。
- ステップ3は「自動更新の目的」の画面に続けて、5つの設定手順を画像付きで1画面ずつ表示する。lifelify を閉じたときに予定を壁紙へ反映する目的と、ショートカットを追加するだけでは自動更新されないことを説明する。
- 「戻る」「次へ」で進め、ショートカットアプリから戻っても現在のページを維持する。押す項目・戻るタイミング・確認内容を明記し、最後の確認画面の「設定を確認しました」で「設定できました」画面へ進み、「閉じる」で案内を終了する。完了表示は利用者の確認に基づく。アプリ切替や初回表示済みの記録を、ショートカットの追加・設定完了とは判定しない。
- 手動作成の詳しい手順と画像の書き出しは、「※ 追加できない場合は、手動で作成できます。」から開く。リンクは通常の設定ページ最下部と、導入シートのステップ2（ショートカット）の最下部に表示する。
- 大きい文字でも説明が切れないように内容をスクロール可能にし、主操作は画面下部に表示する。

## フィードバック & Haptics
- 完了アクション (タスク完了、習慣達成、日記保存) 時に `UINotificationFeedbackGenerator().notificationOccurred(.success)` を実行。
- 習慣の連続達成時などは視覚的演出と共に強めのフィードバックを検討。

## Habits & Countdown
- 習慣リストの先頭に説明文を配置し、SF Symbols 名称が難しい場合はアイコン選択グリッドで代替。  
- カラー選択はパレット式。  
- 各習慣行をタップで編集モーダル。  
- Weeks × Habits のマトリクスで完了チェックが一目。
- 年間草 (53 週 × 7 日): 達成率 5 段階の緑グラデーション。今日セルは白枠/軽い拡大で強調し、初期表示は右端 (今日を含む週) が見える位置まで自動スクロール。セルタップで当日サマリーシートを開き、予定されている習慣のみをリスト表示し、そこでチェック ON/OFF 可能 (予定外の日付は編集不可)。
- 年間草カード下に統計ラベルを配置し、「今年の平均達成率」「今月の平均達成率」を%表示。
- ミニ草 (各習慣 8 週間): 小さな矩形を横スクロールで並べ、今日セルに細枠マーカー。行タップで詳細ビューへ。
- HabitDetailView: 直近ヒートマップ + ストリーク/合計達成数。履歴リストは予定日だけトグル表示し、非予定日は「予定なし」で読み取り専用。編集ボタンから習慣編集に遷移。

## Health
- 「ヘルスケア」タブ:  
  - サマリカードから歩数/睡眠履歴を開けるようタップ可能に。  
  - 歩数歴: バー上に歩数ラベル、横スクロールで全期間。  
  - 睡眠: 途切れない縦棒 (RectangleMark) + 期間注釈。棒内部に睡眠時間テキスト。  
  - 履歴ビュー: 範囲 (週/1か月/6か月/1年) 切替 & 横スワイプで移動。  
  - Apple フィットネス (ムーブ/エクササイズ/スタンド) の最新値 or 平均を表示。  
  - 相関グラフ: 睡眠 vs 歩数、点の色で体調スコア、注釈で気分絵文字。

## Diary
- テキスト入力欄は空のプレースホルダーで開始。削除不要。  
- 体調 Picker: 絵文字表示 (😫~😄)。  
- 気分 Picker: `MoodLevel` (emoji + ラベル)。  
- 写真: PhotosPicker から追加、最大 50 枚、現在枚数を注記。  
- ロケーション: 「訪れた場所を保存しておきましょう」メッセージ + MapKit 検索シート。  
- 保存時に位置情報/説明文/写真パスを DB へ。

### 振り返りの地図
- 場所名は点の下に地図標準のタイトルとして表示する。日付・回数の表示制御と分けて扱い、場所名を一律に非表示にしない。
- 遠い縮尺は白い縁のある小さな点を使い、地図上で訪問場所の分布を見渡せるようにする。異なる場所の点はまとめない。
- 点の直径は表示中の訪問日数で6 / 7 / 8pt（1日 / 2〜4日 / 5日以上）とし、ズームしても同じ大きさを保つ。控えめな差で回数を伝え、タグの意味が変わらないよう、回数による色の濃淡は付けない。
- 遠い縮尺は代表タグの単色、拡大時は最大9色の等分の丸を表示する。小さい点の色を隠さないよう、白い外縁は0.5pt、色の境界は0.25ptとし、混色せず元のタグ色を残す。タグ未設定はグレー。
- 色も訪問日数も表示期間・タグフィルタに合わせる。代表タグは該当する訪問に付いている頻度で選び、等分の色の順番は安定させる。単一タグの絞り込みでは、その色で表示する。
- 拡大時に回数と従来の日付要約を表示する。日付要約の省略ルールは変えない。ラベル同士の画面上の重なりを避け、選択中、次に最新の訪問がある場所を優先する。非表示にするのはラベルだけで、点は残す。
- 選択は外側の輪で示し、訪問回数による点の大きさと区別する。点のタップと既存の場所一覧から詳細を開く。
- タグ管理に色の変更操作を置く。既存タグ・新規タグには初期色を自動で割り当て、名前変更・並べ替えでも保存済みの色を維持する。
- 地図の集計と表示情報は永続キャッシュを使い、再起動後も利用する。日記本文や予定などの変更、地図の移動だけで訪問回数・タグ色・日付要約を作り直さない。
- 地図に関係するデータの編集時は、関係する場所だけを更新する。通常ストアとシミュレーターデモは別のキャッシュを使う。元データを正とし、キャッシュの破損・形式変更や言語・カレンダー・タイムゾーン変更時は再生成する。

## カレンダー & 予定
- カレンダー名ではなくカテゴリ/用途をラベルで表示し直感的に。  
- 予定追加/変更: Today / カレンダー から開ける `CalendarEventEditorView` で完結。タイトル、詳細メモ、カテゴリ、時間、通知を同一シートで編集する。
- ダブルタップ追加の説明文を Today / カレンダー の上下に配置。

## ナビゲーション & 操作メモ
- Today や カレンダー のタイムラインに「ダブルタップで追加」注記を設置。
- カレンダー週ビューで別日を開いた際は「今日へ戻る」ボタン。今日を表示中は非表示。
- 週ビューの移動は週単位、月ビューは月単位。週カレンダーの時間軸左側がずれないよう GeometryReader で調整。
- 予定/タスク/習慣などの編集シートのタイトル・説明は日本語で統一。

## 表記ルール
- 日付・曜日・時間は iOS のアプリ言語・地域設定に従って表記する。表示用途の `DateFormatter` は `Locale.autoupdatingCurrent` または `Date.FormatStyle` を使い、固定の `ja_JP` / `dateFormat` に戻さない。
- ユーザーが保存した本文、カテゴリ名、タグ名、場所名、手紙本文、買い物の商品名・購入先名・メモは翻訳・上書きしない。組み込みカテゴリや組み込みタグは保存キーと表示名を分け、表示名だけ `Localizable.xcstrings` で翻訳する。

## 日記写真の保存設定
- 設定のストレージ欄から「日記の写真とiCloud」を開き、2種類の保存方法と「すべての写真をiCloudに同期」を表示する。未同期枚数・進捗・失敗時の再試行を同じ画面にまとめる。
- 容量節約でもカレンダーには全写真分の永続サムネイルを使う。拡大表示ではサムネイルを先に表示し、取得中・取得失敗・再試行を写真上に表示する。
- サムネイルから本体画像への切り替え・再試行で、表示中の写真を消したり倍率と位置をリセットしたりしない。全体が画面に収まる状態を1倍とし、画面回転でも倍率と可能な範囲の注視位置を維持する。ピンチ縮小・ダブルタップで全体表示に戻れるようにする。
- 独自ログイン画面は追加しない。iCloud容量の使用、日記から削除した写真のクラウドコピーも削除されることを説明する。
- 仕様と5言語の表示範囲は `docs/diary-photo-icloud-sync.md` を参照。

## 買い物のChatGPT連携（DEBUG専用）
- 「lifelifyのプラグインを開く」はHTTPSの個別リンクを使用し、ChatGPTアプリ内に留まることを保証する表現はしない。プラグイン画面を開くこと、ChatGPTで接続を始めること、lifelifyで許可することを区別する。
- 買い物の通常操作はそのまま使い、連携はメニューから任意に開始する。Cloudflareアカウント作成の説明とApple標準ボタンを用い、ChatGPTのログインIDはlifelifyで入力させない。
- アカウント作成と権限承認は別の操作。承認前に要求元、読み書きの権限、現在のアカウント、自分が開始した接続であることを示す。
- 入ってきたUniversal Linkをロック中も保持し、解除後に同じ承認画面へ進む。表示済みの画面もロック中は覆い、権限を送信しない。
- 許可／拒否の後は既定ブラウザで接続を再開する。ChatGPTアプリや元のタブに直接戻れるとは表示しない。Cookieが一致しない場合は決定を保持し、元の接続画面へ戻る案内を表示する。結果不明のMCP書き込みを再送するボタンは出さない。
- 買い物の同期は「買い物データの同期を開始」で任意に始める。商品名・購入先名・メモが本人のCloudflareアカウントに保存されること、手紙のE2EEとは別であることを開始前に示す。アカウント作成や接続承認だけでアップロードされると誤解させない。
- 初回同期はクラウドの既存商品を残し、同名でも別IDのデータは別の商品として保持する。アプリを開いた時や手動操作でクラウドの変更を取り込むことを説明し、即時反映やバックグラウンドのプッシュ同期を約束しない。
- 同期状態、送信待ち、エラーと再試行を同じ画面にまとめる。競合時は端末とクラウドのどちらを残すか選べるようにし、アカウント不一致では送信を止めて理由を表示する。同期が未完了なら完了と表示しない。
- UI文言は `ja` / `en` / `ko` / `zh-Hans` / `zh-Hant` を揃える。利用者が保存した商品名・購入先名・メモは翻訳しない。
