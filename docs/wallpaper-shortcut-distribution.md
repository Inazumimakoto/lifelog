# 壁紙カレンダー用ショートカットの配布

`docs/requirements.md` §4.11 の運用手順。完成済みショートカットを Apple の iCloud 共有リンクから追加できるようにする。修正版の [lifelify 壁紙カレンダー](https://www.icloud.com/shortcuts/9978955ab3c148c796728101b02c3802) をアプリの追加先に採用する。署名済み配布内容がロック画面だけを対象にしていることは確認済み。別端末・別利用者での実行確認は未実施。

## 利用者の流れ

ロック画面カレンダーをその端末で初めて開くと、専用シートの「ようこそ」から始める。全体は「壁紙を作る → ショートカットを追加 → 自動更新を設定」の3ステップとし、各ステップの中も1画面1目的で順番に案内する。利用可否は既存の `MonetizationService.canUseWallpaperCalendar` に従う（現在の一時的な課金無効化も継続）。

| ステップ | 画面の順序と目的 |
| --- | --- |
| 導入 | 「ようこそ」と「ロック画面で、予定をひと目に」で、これから行う設定を案内する |
| 1. 壁紙を作る | 背景写真／背景色を選ぶ → レイアウトと表示する週数を決める → 表示する情報（プライバシー）を決める → 独立した完成プレビューで「この壁紙でよろしいですか？」と確認する |
| 2. ショートカットを追加 | ショートカットを使う理由を知る → 共有リンクから追加する → 一度実行してロック画面を確認する |
| 3. 自動更新を設定 | 自動更新の目的を知る → 5つの設定手順を画像付きで1画面ずつ進める → 最後に「設定を確認しました」を押す |
| 完了 | 「設定できました」画面の「閉じる」で案内を終了する |

背景写真の位置や拡大率は、案内の上に開く調整シートで整える。背景選択、レイアウト・週数、表示する情報、完成プレビューはそれぞれ別画面にし、1つずつ決める。プレビューを確認してからショートカットの設定へ進む。

ショートカットの追加画面では、共有リンクを開いて「ショートカットを追加」を押し、lifelify に戻る手順を案内する。動作確認画面では、ショートカットアプリで追加したショートカットを一度実行し、必要な許可とロック画面の表示結果を確認して lifelify に戻る。必要に応じて自分の端末の対象壁紙を選ぶ。

lifelify が予定入りの画像を作り、Apple のショートカットがロック画面の壁紙に設定する。自動更新は、その処理を lifelify を閉じるたびに実行するための設定として説明する。共有ショートカットの追加だけではオートメーションは作成されない。

各ページで操作先、押す項目、lifelify に戻るタイミング、確認する内容を示す。「次へ」「戻る」で移動し、ショートカットアプリから戻っても、シートを開いている間は現在のページを保つ。最後の確認画面の「設定を確認しました」で独立した「設定できました」画面へ進み、「閉じる」で終了する。この完了表示は利用者の確認に基づき、アプリが追加や自動更新の完了を検証するものではない。インストール済み状態も記録しない。

初回表示時に、案内を表示したことだけを端末内へ保存する。途中で閉じても次回は自動表示せず、通常の設定ページから背景・表示内容を変更できる。「設定手順をもう一度見る」で「ようこそ」から開き直せる。

通常の設定ページ最下部と、導入シートのステップ2（ショートカット）の最下部に「※ 追加できない場合は、手動で作成できます。」の補助リンクを置く。導入シートではショートカットの段階だけに表示する。手動での作成手順と生成画像の書き出しは、そのリンク先にまとめる。

背景や予定は実行する端末のアプリから読み込む。背景を変更してもショートカットの入れ直しは不要。現在の iPhone の壁紙をアプリが自動取得する仕様ではない。

Apple は [iCloud 経由のショートカット共有](https://support.apple.com/ja-jp/guide/shortcuts/apdf01f8c054/ios)を提供している。[パーソナルオートメーションはデバイス固有](https://support.apple.com/ja-jp/guide/shortcuts/apd690170742/ios)なので、共有リンクの追加だけでは自動更新の設定は完了しない。

## 開発者が作成するもの

配布対象の lifelify をインストールした実機 iPhone で、次の2アクションを持つショートカットを作る。設定項目の名称は iOS のバージョン・言語に合わせて確認する。

| 順番 | アクション | 設定 |
| --- | --- | --- |
| 1 | lifelify「壁紙カレンダーを更新」 | `UpdateWallpaperCalendarIntent` が返す JPEG 画像を次へ渡す |
| 2 | Apple 標準「壁紙の写真を設定」 | 入力は直前の画像。ロック画面のみを対象にし、プレビュー表示・画像の切り取りをオフにする |

固定の写真、写真アルバム、作成者のローカルファイルパスは組み込まない。背景の選択は lifelify 内で済ませる。

対象壁紙の設定には実機での確認が必要。作成者の壁紙番号や端末固有の参照をそのまま配布しない。該当パラメータが対応していれば [読み込み時の質問](https://support.apple.com/ja-jp/guide/shortcuts/apdf330fd3a0/ios)を設定し、対応していなければ受信者が追加後に対象壁紙を選ぶ手順にする。どちらも別端末で実際に使えることを確認する。

実機で動作を確かめたら、ショートカットの共有から「iCloudリンクをコピー」を選ぶ。配布するのはその正式な `https://www.icloud.com/shortcuts/<ID>` リンクとし、ID を推測して作成しない。

## アプリへの組み込み

- `lifelog/Info.plist` の `WallpaperCalendarShortcutURL` に、署名済み配布内容を確認した共有 URL を設定する。採用 URL は `https://www.icloud.com/shortcuts/9978955ab3c148c796728101b02c3802`。実機確認の完了状況は下記に記録する。
- 有効な URL がある場合は、専用シートのステップ2から共有リンクを開く。未設定または URL 形式が不正な場合は、手動作成ガイドを開く。
- 背景選択、レイアウト・週数、表示する情報、プレビュー確認、ショートカットを使う理由、追加、動作確認、自動更新の目的を別画面にする。自動更新の5枚の手順画像はステップ3内で1画面ずつ表示する。手動作成ガイドは通常の設定ページとステップ2の最下部の注記リンクから開けるようにする。
- 初回表示済みのフラグは端末内で保持し、初めて案内を表示した時点で保存する。設定完了やショートカットのインストール状態を示すフラグとして扱わない。
- アプリによる URL 形式の検査は、リンクの公開状態やショートカットの動作を保証しない。共有停止・リンク変更時も配布先の実機で確認する。
- 配布内容を更新した場合は、共有リンクから取り込まれる内容を再確認する。既存の利用者のショートカットが自動更新される前提にしない。

## 配布前の確認

- [ ] 別の iPhone・別の Apple Account で共有リンクを開き、ショートカットを追加できる。
- [ ] 配布対象のアプリで lifelify のアクションが認識され、プレミアム利用権のある状態で手動実行できる。
- [ ] 受信者の写真・予定で画像が生成される。アプリで背景を変えると再追加なしで反映される。背景色だけでも動作する。
- [ ] 受信者が選んだロック画面だけを変更し、ホーム画面や別の壁紙への影響がない。複数の壁紙がある端末でも確認する。
- [ ] プレビュー・切り取りが毎回表示されず、文字が意図せず拡大・欠けしない。
- [ ] 初回の必要な許可を済ませ、自動更新の設定後に lifelify を閉じて壁紙が更新されることを確認する。端末のロック状態などで解除が必要になる条件があれば案内に反映する。
- [ ] `ja` / `en` / `ko` / `zh-Hans` / `zh-Hant` でアプリの案内、App Intent、エラー表示を確認する。配布物に説明・読み込み時の質問・コメントを加える場合も5言語を用意する。
- [ ] 初回だけ「ようこそ」から案内が自動表示され、途中で閉じても次回は通常の設定ページが開く。「設定手順をもう一度見る」も「ようこそ」から開ける。
- [ ] 背景選択・レイアウトと週数・表示する情報・完成プレビューが4つの別画面になっており、写真調整と「この壁紙でよろしいですか？」の確認を経てステップ2へ進める。
- [ ] ショートカットを使う理由・追加・動作確認、自動更新の目的・5つの画像付き手順、完了がそれぞれ独立した画面として順に表示される。
- [ ] 「次へ」「戻る」、外部アプリから戻った際のページ維持、「設定を確認しました」から「設定できました」画面への移動、「閉じる」による終了を確認する。手動作成リンクが通常の設定ページ最下部とステップ2だけにあり、画像書き出しと URL 未設定・不正時の手動ガイドを利用できることを確認する。

確認記録には共有 URL、アプリのバージョン／ビルド、iOS バージョン、機種、確認言語、対象壁紙の選択方法、実行結果を残す。

## 採用した共有リンクの確認記録（2026-09-06）

[lifelify 壁紙カレンダー](https://www.icloud.com/shortcuts/9978955ab3c148c796728101b02c3802) の共有レコードと配布ファイルを読み取り確認した。署名済みファイルを `aea` / `aa` で展開した `Shortcut.wflow` は、同じ共有レコードの未署名データとバイト単位で一致した（1,855 bytes、SHA-256: `761f8bc594ce3b57d82aa5a2397b81fc3cc0aca197ef3edc8aa97eb22fd10274`）。

| 項目 | 確認した値 |
| --- | --- |
| 名前 | lifelify 壁紙カレンダー |
| アクション1 | `com.inazumimakoto.lifelog.UpdateWallpaperCalendarIntent` |
| アクション2 | `is.workflow.actions.wallpaper.set` |
| 画像の入力 | アクション1の出力を直接参照 |
| 対象画面 | `WFWallpaperLocation = "Lock Screen"`。ホーム画面は指定されていない |
| プレビュー | `WFWallpaperShowPreview = false` |
| 切り取り | `WFWallpaperSmartCrop = false` |
| 読み込み時の質問 | `WFWorkflowImportQuestions = []` |
| 対象壁紙の固定参照 | 配布データに「壁紙12」や対象壁紙の端末固有 ID に相当するフィールドは含まれていない |

「壁紙12」が共有時に除去されたのか、端末側で補完して表示されるのかは、この配布データだけでは断定しない。別端末へ追加した際の対象壁紙を確認する。

旧リンク `d9f4e9abf0384b67a34671a6938c8c48` はロック画面・ホーム画面の両方を指定していたため採用しない。現在は修正・再共有が済み、残作業は上記の実機確認。
