# 習慣チェックの差分更新

2026年10月13日。ホームで習慣を1件チェックするたびに、全履歴から当日分を検索し、生成済みの習慣タブの年間集計とカレンダーのキャッシュを全更新していた処理を変更した。

## 更新範囲

- `HabitRecordLookup` は習慣ID・日付から記録の配列位置を引く索引を保持する。初回読込・履歴の全置換時に作り、チェックでは変更した記録だけ更新する。カレンダー・タイムゾーンが変わったときは現在の設定で作り直す。
- 完了日の変更通知は配列代入と索引更新の後に発行する。通常のチェックでは履歴配列全体の比較や、全履歴の再検索を行わない。
- ホームは表示日の該当行だけ更新する。連続日数に影響する過去日のチェックも、対象習慣の行だけ更新する。タイムラインは再公開しない。OSのカレンダー・タイムゾーン変更後は、予定曜日が変わるため一覧を再評価する。
- 習慣タブは変更した日の年間サマリー、変更した習慣のミニ草のセルと週間ステータス、対象習慣のストリークだけ更新する。年間・月間平均はその日の達成率の差分を反映する。非表示中も集計済みデータを保持するため、再表示時に全体を集計し直さない。
- 初回・習慣の設定変更・履歴の全置換では、値だけのスナップショットをバックグラウンドへ渡して年間集計を作る。古い世代の計算結果を捨て、計算中のチェックは完了時に変更した日だけ反映する。日付変更・タイムゾーン変更・アプリ再表示でも対象期間を確認する。
- カレンダーは変更した日のセルを、その日を含む隣接月のキャッシュにも反映する。日詳細は対象習慣の記録だけ更新し、無関係な月・日・タスク索引・タイムラインのキャッシュを保持する。
- 習慣詳細の記録検索と合計達成数も同じ索引を使う。背景のナビゲーションに詳細画面が残っていても、各日ごとに全履歴を探さない。

SwiftDataの保存、ウィジェット更新要求、達成時の触覚フィードバックは維持する。レガシーの同日重複記録について、ホーム・カレンダー詳細・保存は最初の記録、習慣の草は最後の記録、達成演出は1件でも完了している日を使う既存の扱いを保持する。合計・月間達成数は重複レコードも従来どおり数える。

iOS 26.1のシミュレータで回帰テストを実行すると、暗黙のMainActor分離デイニシャライザ経由の解放でSwiftランタイムがクラッシュした。既存のAppDataStoreと同じ空の`nonisolated deinit`を索引・対象ViewModel・CalendarEventServiceに適用した。明示的な解放処理は追加していない。

## 索引検索の測定

20習慣 × 2,000日の40,000記録を使い、実装ファイルを `swiftc -O` でコンパイルして比較した。25回の検索を5セット実行した中央値、1回当たりの時間。初回索引作成、SwiftData保存、画面描画、アプリ全体のタップ応答はこの測定に含めない。

| 処理 | 全履歴の検索 | 保存済み索引の検索 |
| --- | ---: | ---: |
| ホーム用の当日記録一覧 | 58.0197 ms | 0.0012 ms |
| 達成演出用の対象習慣の完了日・当日の完了習慣ID | 2.4034 ms | 0.0022 ms |

返り値の一致と100回の完了反転後の索引・完了日集合の一致も検証した。再現コードは `docs/performance/habit-record-lookup/main.swift`。

```sh
swiftc -O docs/performance/habit-record-lookup/main.swift lifelog/ViewModels/HabitRecordIndex.swift lifelog/Services/HabitRecordLookup.swift lifelog/Services/HabitCompletionQuery.swift -o /tmp/lifelog-habit-record-lookup-perf
/tmp/lifelog-habit-record-lookup-perf
```

## 回帰確認

日付境界・夏時間、重複記録、チェック・解除・連打、対象日以外の更新通知の抑制、平均達成率と全再集計の一致、アーカイブ済み習慣、表示範囲外の履歴、バックグラウンド計算中の変更・全置換・作成日の補正、日付変更、カレンダーの月またぎとキャッシュ保持をXCTestで確認した。ホームの連続日数と1行表示の確認を含め、追加した回帰テストは31件。

署名付きiPhone 17 Pro / iOS 26.1シミュレータで全358件が成功（失敗0件、スキップ0件）。連続日数の表示有無・桁数が変わっても、5言語と通常／大きい文字で行高が同じことを検証した。描画画像でも名前の先頭とチェックの位置を確認した。
最終コードのgeneric iOS向けReleaseビルドも成功し、`git diff --check`でエラーはなかった。

```sh
xcodebuild test -project lifelog.xcodeproj -scheme lifelog -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -parallel-testing-enabled NO
xcodebuild -project lifelog.xcodeproj -scheme lifelog -configuration Release -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
git diff --check
```

実機のReleaseビルドでのタップ応答とフレーム時間は別途計測が必要。メインアクター上のSwiftData保存、配列のコピーオンライト、対象習慣のストリーク計算は残るため、索引検索の数値をアプリ全体の速度として扱わない。
