# 統合ライフログアプリ要件定義書

最終更新: 2026-10-12

作成者: Codex (ユーザー要望をもとに作成)

---

## 1. アプリ概要

バレットジャーナル (Bullet Journal) の思想をベースに、予定・タスク・日記・習慣・ヘルスデータなど日々の記録を 1 つの iOS アプリで統合管理する。参考イメージは COMO Bujo。  
主要タブ: ホーム / カレンダー / 買い物 / 習慣 / ヘルス。

## 2. ターゲットユーザー
- iPhone ユーザー (iOS 17 以上を推奨)
- 日記・タスク管理・ヘルスケア・生活管理を 1 アプリで完結したい人
- バレットジャーナルやメンタル/感情トラッキングを好むユーザー

## 3. 利用シナリオ
- 朝: 今日の予定/習慣/体調指標を確認
- 夜: 日記を書き、写真・気分・体調・位置情報を残す
- ヘルスケア (睡眠・歩数・Apple フィットネス) データは自動取得
- 記念日カウントダウンを随時確認
- 日常の買い物を購入先ごとにまとめ、店内でチェックする
- 習慣や目標進捗をタイムライン・グラフで可視化

## 4. 機能要件

### 4.1 Today (ホーム)
- 日付表示
- カレンダー予定 (EventKit 読み取り) を文字 + タイムライン表示で可視化
- 今日が期限の ToDo、今日対象の習慣
- ホームの習慣行は1行で、習慣名の右に連続日数を表示し、名前の左端と右端のチェック位置を固定する。長い名前は末尾を省略し、連続日数が0の場合はバッジを表示しない。
- ヘルスサマリ (歩数 / 睡眠 / エネルギー)
- 共通メモカード (タスク直下に配置)。プレビュー + 最終更新表示、Today 右上ボタン/カードタップで編集 (TextEditor、オートセーブ)
- セクション順序: 予定 → タスク → メモ → 習慣 → ヘルスサマリ → 日記
- 前日の睡眠時間、今日の歩数、歩数/睡眠タイムラインの関係グラフ
- 日記の記入状況とショートカット
- 予定カードをタップで編集
- ヘッダーに天気情報 (最高・最低気温) を大きなフォントで併記
- 右下に FAB (Floating Action Button) を配置し、タスク・予定の追加へ素早くアクセス
- 右上ツールバー: メモ / ポップアップリスト (予定・タスク) / 設定

### 4.2 カレンダー (月ビュー)
- 月表示 (標準 or カスタム)・日付タップで詳細へ
- 設定の「週の始まり」で日曜 / 月曜を選択できる。初期値は日曜。予定の月・週表示、振り返り、予定ウィジェット、壁紙カレンダーに共通で反映し、変更時は選択日を保ったまま表示を更新する。
- カレンダーの日別表示データは再描画ごとに全件を走査せず、元データ・開始曜日の変更に合わせて更新する。
- EventKit で予定を読み取り (タイトル / 時間 / カレンダー名)
- アプリ内から予定作成・編集を可能にする (カレンダー名の代わりにカテゴリ表記、詳細メモ対応)
- 予定には任意のURLを1件保存できる。ホーム・予定リスト・日別詳細にリンクを表示し、タップで開ける。繰り返し予定の各回にも引き継ぎ、今回だけの変更でURLも変更できる。
- アプリ内の予定は毎日・毎週・隔週、複数曜日、終了日を指定して繰り返せる。予定本体のルールと各回の例外を保存し、表示する期間だけ予定を生成する。
- 繰り返し予定の編集は保存時に今回のみ・今回以降・シリーズ全体の範囲を選ぶ。繰り返しルールを変更した場合は今回以降・シリーズ全体を選べ、シリーズ管理からの編集はシリーズ全体に適用する。今回以降の変更はそれ以前の予定と履歴を残す。繰り返しを「なし」にする場合は選んだ回を単発予定として残し、選択した範囲の繰り返しを終了する。
- 曜日や周期の変更で既存の休み・変更を対応付けられなくなる場合は、保存前に対象と扱いを確認する。対応付けられない変更済みの回は初期状態で単発予定として残す。対応付けられない休みの設定を除く処理も、確認を受け入れて保存した時にだけ反映する。範囲選択や確認のキャンセルでは保存データを変更しない。
- 保存範囲の選択と例外の確認はホーム・予定リスト・日別詳細・カレンダーの編集シートで共通化する。外部カレンダーの予定は読み取り専用とし、新規作成は保存範囲の選択を挟まない。
- 「今回以降」の変更で保存上の予定が期間ごとに分かれても、共通の繰り返しグループIDで元の予定との関係を保持する。「繰り返し予定をすべて削除」は変更前・変更後のどの回から選んでも、同じグループの全期間と各回の例外を1回で削除する。繰り返しグループの判定にはタイトル・日付・URLの一致を使わず、グループIDのない既存予定はそれぞれ独立した予定として扱う。
- 繰り返し予定は今回だけの変更に対応し、削除は「予定を削除」から今回のみ・この週・今回以降・シリーズ全体の範囲を選ぶ。「この週」は同じシリーズの予定が表示週に複数ある場合のみ選べる。今回のみ・この週は例外として保存し、休み・変更した日の一覧から元に戻せる。今回以降は過去を残して終了し、シリーズ全体は過去の予定と例外も削除する。例外は予定本体のIDと元の開催日時で識別し、振替や休止で周期をずらさない。
- 繰り返しと例外の結果をホーム・月/週カレンダー・予定リスト・通知・予定ウィジェット・壁紙カレンダーで共通化する。日時は保存したタイムゾーンの暦で計算し、終日・複数日・夏時間・表示期間をまたぐ振替を扱う。
- 予定リストは繰り返し予定を初期状態で前後1年分表示し、表示期間と前後への追加表示操作を示す。単発の保存予定は期間外でも一覧に残す。外部カレンダーの予定は読み取り専用のまま扱う。
- 予定リストの「繰り返し予定を管理」から、全回を休みにしたシリーズや終了済みのシリーズにもアクセスできる。「この週」は端末の表示タイムゾーンと週の始まりに従い、振替後の表示日を基準に選んだシリーズの各回を休みにする。
- ホーム・予定リスト・日別詳細の編集シートとカレンダーのタイムラインから、同じ削除範囲の選択を使う。単発予定は通常の削除確認とし、外部カレンダーは削除操作を表示しない。
- 繰り返し通知は休み・振替を反映した一回通知とし、外部予定と合わせて通知時刻が近い48件を予約する。起動・前面復帰や予定変更時に予約を補充し、無期限の通知を一括登録しない。
- 繰り返しの展開は規則に該当する日・週だけを進め、表示用の整列は最後に1回行う。週まとめ削除は例外の取得・保存・公開更新を各1回にまとめる。削除範囲の週件数は選択画面を開く時だけ計算し、入力や再描画では展開しない。通知なしのシリーズは通知用の展開から外し、メモ・URLだけの変更では通知を再登録しない。
- Today と同様に右下に FAB、右上に統一されたツールバー (メモ/リスト/設定) を配置

### 4.3 ToDo
- CRUD + 完了チェック
- タイトル必須、詳細/期限/優先度(低~高) 任意
- タスクには任意のURLを1件保存できる。ホーム・タスクリスト・日別詳細のタスク行から開け、リンク操作で完了状態を切り替えない。
- DB 永続化 (SwiftData。App Group 共有ストアでウィジェットからも読み取り)
- Today では今日締切のみ、その他の日付タスクはタスクリストから追加する導線説明

### 4.4 日記 (Diary)
- 1 日に 1 件 or 複数エントリ
- 入力: テキスト (初期値は空)、写真(最大 50 枚、PhotosPicker から取得し Documents 保存)、気分スコア(1~5)、体調(5段階・絵文字)、位置情報 (地図を動かして複数スポットを選択・保存)
- 体調/気分/睡眠/歩数の相関を Health 画面にグラフとして表示
- 日記のAI採点、期間を指定したAI分析、AI分析用データ書き出しは次回リリース版から廃止する。通常の日記・健康記録・保存済みデータは維持し、日記DBにAI結果の保存項目はないため、この撤去にDB移行はない。公開済み旧版とサーバーの退役作業は `docs/ai-analysis-retirement.md` を参照。

#### 4.4.1 訪問タグ（場所訪問コンテキスト）
- タグは「場所そのもの」ではなく「その日その場所の訪問」に付与する（同一店舗でも日付ごとに意味を分ける）。
- 1訪問あたり複数タグを付与可能。上限は 8 件。
- タグ初期値（初回のみ自動作成）: ご飯 / カフェ / 仕事 / 勉強 / 買い物 / 旅行 / 観光 / 運動 / 用事 / 友人 / 家族 / デート
- ユーザーは自由タグを追加可能。プリセットも自由タグも同一管理（編集・並び替え・削除可能）。
- タグ管理でタグごとの色を変更可能。初期色は自動で割り当て、既存タグも色付きで読み込めるようにする。色は保存し、名前変更・並べ替えでも維持する。
- タグ名ルール: 1〜15文字、前後空白を除去、同名重複禁止。絵文字は許可。
- タグ名変更は全訪問データへ一括反映する。
- タグ削除は全訪問データから削除する（削除件数付き確認ダイアログを表示）。
- 場所追加直後にタグ選択シートを表示し、日記編集画面の場所行から後編集も可能にする。
- 振り返り地図のタグフィルタは OR 条件（選択タグのいずれか一致）で判定する。
- 「未タグ」フィルタを提供し、他タグとの同時選択時も OR 条件で扱う。
- 振り返り地図のUIは常時タグ全表示しない。上部は「絞り込み」導線 + 選択中タグのみ表示し、詳細選択はシートで行う。

#### 4.4.2 振り返り地図の場所マーカー
- 場所名は点の下に地図標準のタイトルとして表示する。日付・回数の拡大時表示とは分け、場所名を一律に非表示にしない。
- 遠い縮尺では場所を小さな点で表示し、異なる場所の点をクラスタや件数付きの集合マーカーにまとめない。
- 色はタグ、点の大きさは訪問回数を表す。回数は表示期間とタグフィルタに一致する記録から集計し、同じ場所の同じ日は1回と数える。
- 点の直径は、1回が6pt、2〜4回が7pt、5回以上が8ptとし、地図を拡大しても大きくしない。選択中は外側の輪で強調する。
- 遠い縮尺では最も多く付いているタグの単色を使う。未タグはグレー。タグフィルタで1つのタグを選んだ場合は、そのタグの色を使う。
- 拡大時は、該当する訪問によく付いているタグを最大9色まで選んで丸を等分する。色を混ぜず、分割の順番は固定する。全タグは詳細で確認できる。
- 十分に拡大したときに回数と日付を表示する。日付の内容と省略方法は従来どおり（同月では最新3日、月をまたぐ場合は最新2日を表示し、残りは件数で省略）とする。
- 画面上で日付・回数のラベルが重なる場合は、選択中の場所、次に最新の記録がある場所を優先して表示する。ラベルを省略しても場所の点を残す。近い場所は地図を拡大して選ぶ。
- 地図用の集計と表示情報は端末内にキャッシュし、アプリ再起動後も再利用する。日記本文・予定・ヘルス情報など、地図に関係しない変更では再集計しない。
- 座標の空間索引を使って、全縮尺で画面とその周辺にある場所だけを描画する。地図移動中は周辺の描画を再利用し、日付ラベルの座標変換・重なり判定は移動が落ち着いてから行う。タップは近傍の候補だけを画面座標で判定し、点より広いタップ範囲を保つ。期間・タグフィルタの切替で日記の場所データを作り直さない。
- 日記の場所・日付・写真・訪問タグが変わった場合は、追加・変更・削除に関係する場所だけを更新する。タグの色・表示名・並び順を変更した場合も、そのタグを使う場所の表示情報だけを更新する。
- キャッシュは通常ストアとシミュレーターデモのストアで分離し、元の日記・タグデータを正とする。キャッシュの欠損・破損・形式変更、アプリ言語・カレンダー・タイムゾーンの変更時は、必要な情報を元データから再生成する。

### 4.5 カレンダー詳細 (Bujo)
- 週 / 月切替 (週は週次カレンダー + タイムライン、月は従来表示)
- 週タイムライン: 時間軸整列、重なり解消、下部に日詳細 (月表示と同じ内容)
- 週移動は 7 日単位、月ヘッダーは数字表記 (例: 2025年11月)
- 今日以外の日選択時のみ「今日へ」ボタン表示
- 日付ダブルタップで予定/タスク追加できる旨を明示
- 予定/タスクをカレンダー上からも追加・編集可能
- 他日へ移動後に戻るボタン

### 4.6 習慣 (Habit Tracker)
- 登録: タイトル / アイコン (SF Symbols を候補グリッド表示) / カラー (パレット) / 繰り返し設定 (毎日・平日・カスタム)
- HabitRecord: 日付・習慣 ID・完了フラグ
- 習慣チェックは習慣ID・日付の索引を使って当日の記録とホームの該当行だけ更新する。年間草・個別の草・達成率・ストリーク・カレンダーは変更した習慣と日付だけ差分更新し、非表示タブも集計済みデータを保持する。初回や履歴の一括置換時の全体集計はバックグラウンドで行い、計算中のチェック変更を失わない。
- UI: 週間グリッド (横:日付 × 縦:習慣)・Today に本日分を表示
- ホームの連続日数は習慣タブと同じ予定日単位の現在ストリークを使う。表示日が予定日で未完了なら0とする。
- 年間草 (53 週 × 7 日のヒートマップ): 達成率 5 段階の緑グラデ、今日マーカー付き。右端が最新週になるよう自動スクロール。セルタップで当日サマリーシートを開き、その日「予定されている習慣のみ」をリスト表示し、チェック ON/OFF 操作が可能 (予定外の日付は編集不可)。
- 年間草の下に統計表示: 今年の平均達成率 / 今月の平均達成率 (scheduledCount > 0 の日のみ平均)。
- 各習慣のミニ草 (直近 8 週間) を行内に表示。今日マーカー付き。タップで詳細へ遷移。
- HabitDetailView: 直近のヒートマップ + 履歴 (予定日だけ編集可) + 現在/最高ストリークと合計達成数。既存習慣の編集導線あり。

### 4.7 記念日 (Anniversary / Countdown)
- 登録: タイトル / 日付 / 種別 (countdown/since) / 毎年繰り返し
- 表示: D-xxx / D-0 / +xxx

### 4.8 ヘルスケア
- データ: 歩数 / 睡眠 / Apple フィットネス (ムーブ・エクササイズ・スタンド) / 活動量
- 動作: 初回権限取得 → 許可済みのみ読み込み。Today: 当日データ、Health タブ: 週・月・半年・年グラフ
- 直近1週間の平均は維持し、歩数・睡眠・健康状態・Apple フィットネスの各カードから詳細履歴を開く。平均は記録のある日だけで計算し、欠測を0に置き換えない
- 健康状態の推移は、歩数（歩）・睡眠（時間）・気分（1〜5）・体調（1〜5）を同じ日付軸で縦に揃える。日記のみの日も表示し、未記録の気分・体調を中立に補完しない
- 睡眠グラフは起床日ごとの就寝〜起床が分かる時刻タイムライン。実測の覚醒・レム・コア・深い睡眠・段階不明を色分けし、日詳細で各段階の時間と割合を確認する。段階データがない日は就寝・起床の帯のみ表示し、推測した睡眠品質スコアを表示しない。夏時間の切り替えは現地時刻で分割し、時計が戻る日の切り替え前後を左右の帯で示す
- 睡眠時間は睡眠中の区間のみを数え、覚醒・ベッド時間を除く。日付をまたぐセッションを先に構成して起床日に割り当て、複数ソースの重なりを二重計上しない。日別合計は昼寝を含み、就寝・起床は最長の主睡眠の時刻とする。詳細段階のあるソースを優先し、Apple ヘルスケア独自のソース優先順位との完全一致は保証しない
- Apple フィットネスは HealthKit の日別活動サマリーから実値・実目標・ムーブの単位（kcal/分）を取得する。固定目標や時間からカロリーへの換算は使わず、未取得の値・目標は明示する。**日別目標・ムーブモードの任意項目を保存モデルへ追加（既存データを保持する追加変更）**。新しい活動サマリー読み取り権限は「ヘルスケア連携を確認」から取得する
- 履歴ビュー: 範囲 (週/1か月/6か月/1年) 切替 + 前後移動。日付を選択して日別の実値を確認し、長期間は表示密度に応じて日平均を集計して単位を明示する

### 4.9 設定 (Settings)
- 予定のカテゴリ通知: 新しく作るカテゴリ通知設定はオフを初期値とし、「カテゴリごとの通知設定」をオンにしても各カテゴリを自動でオンにしない。保存済みのオン・オフと通知時刻は親スイッチの切り替え後も保持する。
- 開始前の通知は、カテゴリ通知設定と予定の個別編集で共通して1・2・3・5・10・15・30分前、1時間前、1日前から選べる。
- 予定のカテゴリ: 設定の「カレンダー」セクションに独立した入口を置き、カテゴリ名・色の追加・編集・削除を共通の管理画面で行う。予定作成・編集とカレンダー連携のカテゴリ選択画面からも「カテゴリを管理」で同じ画面へ進める。選択行は選択、管理行は編集に役割を分ける。
- カレンダー連携: 外部カレンダーとアプリ内カテゴリのマッピング設定
- 連携画面は表示するカレンダーと表示しないカレンダーを分け、iOS側のカレンダー色とアプリの表示先カテゴリ色を別々に示す。カテゴリの色だけを変更しても連携一覧・ホーム・カレンダーへ即時反映し、予定の再取得や再集計を必要としない。
- カテゴリ名の変更は同じカテゴリを使う全カレンダー・保存予定へ反映し、カテゴリ選択を閉じるだけでは設定を書き戻さない。カテゴリ削除時は予定を残して既存の別カテゴリへ移す（残るカテゴリがない場合は「仕事」を用意する）。iOSで削除したカレンダーは連携一覧から除外する。
- カテゴリの編集は保存時に反映し、空名・重複名を拒否する。削除の確認には移動先を明示する。名前変更・削除は編集中の予定と保持している下書きにも反映し、個別の通知設定を保つ。削除・改名した初期カテゴリを次回起動時に復活させない。
- カレンダーの未許可・読み取り不可・カレンダー未登録状態を区別して案内する。未許可ならアクセス許可、読み取り不可なら設定アプリへの導線を用意し、画面表示・アプリ復帰・手動更新で一覧を再確認する。
- プライバシー: アプリロック機能 (Face ID / Passcode / Touch ID)。バックグラウンド遷移時にロック、復帰時に認証要求。
- ヘルスケア: OS設定へのリンク案内
- サポート: アプリ内レビュー依頼 (条件付き自動トリガー + 手動ボタン)、開発者への問い合わせメール作成 (端末情報自動挿入)

### 4.11 ウィジェット / 壁紙カレンダー
- WidgetKit 拡張 (`LifelogWidgets/`): 予定 / 記念日 / メモ / 習慣の4種。App Group 経由で SwiftData ストアを共有
- 予定ウィジェットの中サイズ: 左に今日の予定・未完了タスク、右に当月のミニカレンダーを表示。今日を丸で強調し、予定のある日に点を付ける。日付タップでアプリの該当日を開く
- シミュレーターの表示確認: Debug + iOS Simulator の通常起動では、初期状態で専用デモを有効にする。`group.lifelog.screenshots/simulator-demo.store` のみに予定・タスク・習慣と達成記録・記念日・メモ・ヘルスサマリー・買い物・ローカル手紙と、振り返り地図用の全国約1,000地点の日記を保存する。再起動で消えたり、同じデータが重複したりしない。地図サンプルは47都道府県に分布し、訪問回数1 / 3 / 6回、未タグ・単色・最大9色の例を含む。設定はシミュレーター内に保持し、日付タップやアイコンからの再起動でも同じデモを表示する。実機・Release・XCTest ホストは無効。通常ストアの移行・CloudKit・外部カレンダー/ヘルス取得・実アカウントの更新・買い物同期はデモ中に行わない
- デモを終了する場合はシミュレーターのアプリを終了し、`-simulator-demo-off` を付けて再起動する。シミュレーター専用のクラウド確認ストアに切り替わり、デモデータ自体は専用ストアに残す。無効設定は次回も維持し、`-simulator-demo-data`（または旧 `-screenshots-mode`）で再び有効にできる
- 壁紙カレンダー: App Intents (`UpdateWallpaperCalendarIntent`) が利用者の背景写真・背景色・予定・表示設定から画像を生成し、ショートカットの標準アクションでロック画面に設定する。配布物に作成者の写真や端末固有の壁紙参照を固定しない
- 初回導入: ロック画面カレンダーをその端末で初めて開いたときだけ専用シートの「ようこそ」を自動表示し、「1 壁紙を作る → 2 ショートカットを追加 → 3 自動更新を設定 → 完了」へ進む。各画面は1つの目的に絞る。初回表示時に端末内へ表示済み状態を保存し、途中で閉じても次回は自動表示しない。通常の設定ページには背景・表示内容の編集と「設定手順をもう一度見る」を用意し、再表示も「ようこそ」から始める
- ステップ1は、背景写真／背景色の選択、レイアウトと表示する週数、表示する情報（プライバシー）、壁紙の完成プレビューの4画面に分ける。写真の位置や拡大率の調整は案内の上に別シートで開く。プレビュー画面では「この壁紙でよろしいですか？」と確認し、利用者が確かめてからステップ2へ進む
- 背景写真はピンチで写真全体が収まる倍率まで縮小でき、ドラッグで位置を調整できる。写真が届かない部分は写真の端の色を外側へ延ばして強くぼかし、写真の外周を幅のある滑らかなグラデーションでなじませる。写真の中央は鮮明に保つ。調整プレビューと書き出す壁紙は端末の縦向きサイズと同じ配置・ぼかし処理を使い、カレンダーの文字や予定はぼかさない。縮小前に写真の端を延長し、余白の分割画像は描画ピクセルに合わせて重ね、書き出し時の黒い線を防ぐ
- ステップ2は、ショートカットを使う理由、追加、動作確認をそれぞれ別画面にする。画像は lifelify が作り、壁紙への反映には Apple のショートカットを使うことを説明する。`lifelog/Info.plist` の `WallpaperCalendarShortcutURL` から完成済みショートカットを追加し、初回の手動実行・必要な許可・対象壁紙と表示結果を端末上で確認する
- ステップ3はまず自動更新の目的を説明し、その後に5枚の手順画像を1画面ずつ表示する。lifelify を閉じたときにショートカットを再実行するパーソナルオートメーションを作成し、共有リンクだけでは自動更新が設定されないことを伝える。各画面で操作先・押す項目・アプリに戻るタイミング・確認内容を示し、「次へ」「戻る」で移動する。外部アプリから戻っても、そのシートを開いている間は現在のページを保つ。最後の確認画面で「設定を確認しました」を押すと、独立した「設定できました」画面へ進み、「閉じる」で終了する。完了表示は利用者の確認に基づき、導入状況の自動検証やインストール済み管理は行わない
- 手動作成は通常の設定ページ最下部と、導入シートのステップ2（ショートカット）の最下部に「※ 追加できない場合は、手動で作成できます。」の補助リンクとして置く。導入シートではショートカットの段階だけに表示する。リンク先に詳しい手順と生成画像の書き出しをまとめる。共有 URL が未設定・不正な場合も手動作成ガイドを開く。配布・実機検証・5言語対応の手順は `docs/wallpaper-shortcut-distribution.md` を参照

### 4.12 日記写真のiCloud保存
- 設定の「日記の写真とiCloud」に一括同期ボタンを置く。初回の手動開始後、新規写真と未完了の処理を起動・復帰時などに再試行する。
- 保存方法は「端末容量を節約」「すべて端末にも保持」の2択。節約時はアップロード成功と同期情報の保存後に高画質版を解放し、拡大中だけ取得する。未同期写真は解放しない。
- 全写真のサムネイルを端末に永続保存する。「今日の一枚」の切り替えと一覧表示は通信を待たずに行える。
- 日記から削除した写真は独立したクラウドコピーも削除する。オフライン時は削除待ちを永続化する。写真アプリには影響しない。
- 通常のiPhone移行で本文・写真ID・サムネイル・同期情報を引き継ぐ。新規インストールだけでの全文復元・複数端末の日記編集同期は今回の対象外。
- 詳細・CloudKitの配布設定・検証範囲は `docs/diary-photo-icloud-sync.md` を参照。

### 4.13 買い物リスト
- 下部タブの3番目に「買い物」を配置し、画面タイトルは「買い物リスト」とする。タブ順は ホーム / カレンダー / 買い物 / 習慣 / ヘルス。
- 購入先を「すべて」「未指定」または利用者が登録した購入先で絞り込む。「すべて」では購入先ごとに商品をまとめて表示する。
- 商品名だけで追加可能。メモは追加画面の「＋メモ」から任意に入力でき、商品の編集画面でも変更できる。数量は独立した項目として扱わず、個数やグラム数などもメモに自由に記載する。旧データの数量は既存のメモを失わずにメモへ移し、移行後も内容を表示・編集できるようにする。購入先未指定でも保存できる。
- 一覧の「商品を追加」から標準の大きなシートで専用の商品追加画面を開く。見出しと件数を「今回追加した商品（件数）」の1行にまとめ、今回追加した商品だけを商品名・購入先・メモとともに即時表示する。各商品の「取り消す」で今回の追加を取り消せる。上部の「閉じる」で購入先ごとにまとまった通常の一覧へ戻り、保存済みの商品は保持する。
- 専用画面の購入先は横スクロールできる選択肢として常時表示し、一覧メニューを開かずに切り替えられる。購入先と商品名の入力部分はタップしやすさを保ちながらコンパクトにまとめる。商品名はカプセル形の入力欄、追加は隣接する丸い「＋」ボタンとする。入力欄はキーボード直上に配置し、キーボードの上に別の「入力を完了」ツールバーや余白を挟まない。
- 商品を連続追加できる。追加するたびに商品名とメモを即時保存し、成功時だけ両方の入力を空にしてメモ欄を閉じる。保存失敗時は入力内容とメモ欄の表示を保持する。追加ボタンと商品名入力の Return のどちらでもキーボードと商品名の入力位置を維持する。メモ欄は画面内の標準の複数行入力とする。選択した購入先は次の入力にも引き継ぐ。特定の購入先を表示している場合は、その購入先を追加時の初期値にする。追加画面を閉じる操作は保存確定のためには不要とする。
- 「未指定」の選択肢は長押しメニューから非表示にでき、購入先の管理画面の「未指定を表示」で再表示できる。この表示設定を端末内に保存し、一覧上部のフィルタと専用の商品追加画面に反映する。非表示でも商品は保持し、「すべて」では未指定の商品を引き続き表示する。未指定を選択中に隠した場合、登録済み購入先があれば先頭を追加時の購入先にする。
- 一覧にはこれから買う商品だけを表示する。商品行全体のタップで購入チェックし、習慣と同じアニメーション付きチェックボックスを使う。商品名・メモのタップも同じ動作に揃え、編集・削除は独立した行メニューから行う。チェック直後は約350ミリ秒のアニメーションを見せてから行を消す。購入済みの一覧や履歴、購入頻度の集計・並べ替え、再購入の操作は設けない。
- 購入チェック後は画面下部に「商品名を購入しました」と「元に戻す」を6秒間重ねて表示する。一覧や「商品を追加」ボタンの位置は動かさない。連続チェックでは最後の1件に更新し、表示期限を延長する。商品はチェック時に端末内の保存データから即時削除し、取り消し用の内容は表示中だけメモリに保持する。「元に戻す」でその商品のID・商品名・メモ・購入先・作成日を保って復元する。表示期限後・画面遷移後・再起動後に購入済みとして残さない。次に必要になった商品は商品追加画面から新しく入力する。
- 商品の編集・削除と、購入先の追加・名前変更・削除・並べ替えに対応する。購入先は店舗名でも「スーパー」などの分類名でも利用できる。
- ローカルの SwiftData の `SDShoppingItem` / `SDShoppingPlace` に永続化する。`ShoppingItem` から購入状態・購入頻度の属性を外し、`SDShoppingItem` の `purchaseCount` / `familyID` も削除する。`SDShoppingItem.purchasedAt` は旧データの購入済み商品を識別する移行用属性としてのみ残し、読み込み時に旧購入済み商品を削除する。既存の未購入商品・購入先・他機能のデータは保持し、他のエンティティの定義は変更しない。追加・変更・購入による削除・取り消しによる復元を端末内へ即時保存し、失敗時は変更を取り消してエラーを表示する。購入先を削除しても商品は削除せず「未指定」に移す。オフラインでも利用でき、買うものは日付をまたいでも保持する。CloudKit による自動同期は行わない。
- HIG に沿った標準のナビゲーション・一覧・入力シートを使う。商品イラストや装飾画像は追加せず、操作を表すアイコンには SF Symbols を使う。
- UI とエラー表示を `ja` / `en` / `ko` / `zh-Hans` / `zh-Hant` で揃える。利用者が入力した商品名・購入先名・メモは翻訳・上書きしない。

### 4.14 外部AI・Cloudflare連携の撤去
- ChatGPT向けのMCP/OAuth、Cloudflareアカウント、機能別共有、クラウド同期・写真コピーのアップロードをアプリから撤去する。通常のローカル利用にアカウント登録を追加しない。
- 日記・買い物・予定などの既存ローカル記録と写真原本、Firebaseを使う手紙・E2EE、既存の日記写真のiCloud保存、MapKit検索を維持する。
- クラウド専用の実行コード・同期用モデル・設定・テスト・展開用プロジェクトを除去する。旧同期モデルを含むSQLiteから通常モデルだけへ開き直した場合にも、通常の13モデルのデータを保持する。
- CloudflareとChatGPT側の停止・削除は別の運用作業であり、ローカルコードの撤去だけで削除済みとしない。対象と順序は `docs/chatgpt-cloudflare-retirement.md` を参照。

## 6. 非機能要件
- iOS 17+ 推奨 (SwiftUI 最新機能)
- 永続化: SwiftData (`Models/SwiftDataModels.swift` の `@Model` 群 + `Services/Persistence.swift`)。App Group 共有ストア。レガシー UserDefaults からの移行は `Services/MigrationManager.swift`
