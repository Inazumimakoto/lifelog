# 統合ライフログアプリ要件定義書

最終更新: 2026-10-08

作成者: Codex (ユーザー要望をもとに作成)

---

## 1. アプリ概要

バレットジャーナル (Bullet Journal) の思想をベースに、予定・タスク・日記・習慣・ヘルスデータなど日々の記録を 1 つの iOS アプリで統合管理する。参考イメージは COMO Bujo。  
主要タブ: ホーム / カレンダー / 買い物 / 習慣 / ヘルス。

## 2. ターゲットユーザー
- iPhone ユーザー (iOS 17 以上を推奨)
- 日記・タスク管理・ヘルスケア・生活管理を 1 アプリで完結したい人
- バレットジャーナルやメンタル/感情トラッキングを好むユーザー

## 3. 利用シナリオ
- 朝: 今日の予定/習慣/体調指標を確認
- 夜: 日記を書き、写真・気分・体調・位置情報を残す
- ヘルスケア (睡眠・歩数・Apple フィットネス) データは自動取得
- 記念日カウントダウンを随時確認
- 日常の買い物を購入先ごとにまとめ、店内でチェックする
- 習慣や目標進捗をタイムライン・グラフで可視化

## 4. 機能要件

### 4.1 Today (ホーム)
- 日付表示
- カレンダー予定 (EventKit 読み取り) を文字 + タイムライン表示で可視化
- 今日が期限の ToDo、今日対象の習慣
- ヘルスサマリ (歩数 / 睡眠 / エネルギー)
- 共通メモカード (タスク直下に配置)。プレビュー + 最終更新表示、Today 右上ボタン/カードタップで編集 (TextEditor、オートセーブ)
- セクション順序: 予定 → タスク → メモ → 習慣 → ヘルスサマリ → 日記
- 前日の睡眠時間、今日の歩数、歩数/睡眠タイムラインの関係グラフ
- 日記の記入状況とショートカット
- 予定カードをタップで編集
- ヘッダーに天気情報 (最高・最低気温) を大きなフォントで併記
- 右下に FAB (Floating Action Button) を配置し、タスク・予定の追加へ素早くアクセス
- 右上ツールバー: メモ / ポップアップリスト (予定・タスク) / 設定

### 4.2 カレンダー (月ビュー)
- 月表示 (標準 or カスタム)・日付タップで詳細へ
- EventKit で予定を読み取り (タイトル / 時間 / カレンダー名)
- アプリ内から予定作成・編集を可能にする (カレンダー名の代わりにカテゴリ表記、詳細メモ対応)
- Today と同様に右下に FAB、右上に統一されたツールバー (メモ/リスト/設定) を配置

### 4.3 ToDo
- CRUD + 完了チェック
- タイトル必須、詳細/期限/優先度(低~高) 任意
- DB 永続化 (SwiftData。App Group 共有ストアでウィジェットからも読み取り)
- Today では今日締切のみ、その他の日付タスクはタスクリストから追加する導線説明

### 4.4 日記 (Diary)
- 1 日に 1 件 or 複数エントリ
- 入力: テキスト (初期値は空)、写真(最大 50 枚、PhotosPicker から取得し Documents 保存)、気分スコア(1~5)、体調(5段階・絵文字)、位置情報 (地図を動かして複数スポットを選択・保存)
- 体調/気分/睡眠/歩数の相関を Health 画面にグラフとして表示

#### 4.4.1 訪問タグ（場所訪問コンテキスト）
- タグは「場所そのもの」ではなく「その日その場所の訪問」に付与する（同一店舗でも日付ごとに意味を分ける）。
- 1訪問あたり複数タグを付与可能。上限は 8 件。
- タグ初期値（初回のみ自動作成）: ご飯 / カフェ / 仕事 / 勉強 / 買い物 / 旅行 / 観光 / 運動 / 用事 / 友人 / 家族 / デート
- ユーザーは自由タグを追加可能。プリセットも自由タグも同一管理（編集・並び替え・削除可能）。
- タグ管理でタグごとの色を変更可能。初期色は自動で割り当て、既存タグも色付きで読み込めるようにする。色は保存し、名前変更・並べ替えでも維持する。
- タグ名ルール: 1〜15文字、前後空白を除去、同名重複禁止。絵文字は許可。
- タグ名変更は全訪問データへ一括反映する。
- タグ削除は全訪問データから削除する（削除件数付き確認ダイアログを表示）。
- 場所追加直後にタグ選択シートを表示し、日記編集画面の場所行から後編集も可能にする。
- 振り返り地図のタグフィルタは OR 条件（選択タグのいずれか一致）で判定する。
- 「未タグ」フィルタを提供し、他タグとの同時選択時も OR 条件で扱う。
- 振り返り地図のUIは常時タグ全表示しない。上部は「絞り込み」導線 + 選択中タグのみ表示し、詳細選択はシートで行う。

#### 4.4.2 振り返り地図の場所マーカー
- 場所名は点の下に地図標準のタイトルとして表示する。日付・回数の拡大時表示とは分け、場所名を一律に非表示にしない。
- 遠い縮尺では場所を小さな点で表示し、異なる場所の点をクラスタや件数付きの集合マーカーにまとめない。
- 色はタグ、点の大きさは訪問回数を表す。回数は表示期間とタグフィルタに一致する記録から集計し、同じ場所の同じ日は1回と数える。
- 遠い縮尺での点の直径は、1回が6pt、2〜4回が7pt、5回以上が8pt。選択中は外側の輪で強調する。
- 遠い縮尺では最も多く付いているタグの単色を使う。未タグはグレー。タグフィルタで1つのタグを選んだ場合は、そのタグの色を使う。
- 拡大時は、該当する訪問によく付いているタグを最大9色まで選んで丸を等分する。色を混ぜず、分割の順番は固定する。全タグは詳細で確認できる。
- 十分に拡大したときに回数と日付を表示する。日付の内容と省略方法は従来どおり（同月では最新3日、月をまたぐ場合は最新2日を表示し、残りは件数で省略）とする。
- 画面上で日付・回数のラベルが重なる場合は、選択中の場所、次に最新の記録がある場所を優先して表示する。ラベルを省略しても場所の点を残す。近い場所は地図を拡大して選ぶ。
- 地図用の集計と表示情報は端末内にキャッシュし、アプリ再起動後も再利用する。日記本文・予定・ヘルス情報など、地図に関係しない変更では再集計しない。
- 日記の場所・日付・写真・訪問タグが変わった場合は、追加・変更・削除に関係する場所だけを更新する。タグの色・表示名・並び順を変更した場合も、そのタグを使う場所の表示情報だけを更新する。
- キャッシュは通常ストアとシミュレーターデモのストアで分離し、元の日記・タグデータを正とする。キャッシュの欠損・破損・形式変更、アプリ言語・カレンダー・タイムゾーンの変更時は、必要な情報を元データから再生成する。

### 4.5 カレンダー詳細 (Bujo)
- 週 / 月切替 (週は週次カレンダー + タイムライン、月は従来表示)
- 週タイムライン: 時間軸整列、重なり解消、下部に日詳細 (月表示と同じ内容)
- 週移動は 7 日単位、月ヘッダーは数字表記 (例: 2025年11月)
- 今日以外の日選択時のみ「今日へ」ボタン表示
- 日付ダブルタップで予定/タスク追加できる旨を明示
- 予定/タスクをカレンダー上からも追加・編集可能
- 他日へ移動後に戻るボタン

### 4.6 習慣 (Habit Tracker)
- 登録: タイトル / アイコン (SF Symbols を候補グリッド表示) / カラー (パレット) / 繰り返し設定 (毎日・平日・カスタム)
- HabitRecord: 日付・習慣 ID・完了フラグ
- UI: 週間グリッド (横:日付 × 縦:習慣)・Today に本日分を表示
- 年間草 (53 週 × 7 日のヒートマップ): 達成率 5 段階の緑グラデ、今日マーカー付き。右端が最新週になるよう自動スクロール。セルタップで当日サマリーシートを開き、その日「予定されている習慣のみ」をリスト表示し、チェック ON/OFF 操作が可能 (予定外の日付は編集不可)。
- 年間草の下に統計表示: 今年の平均達成率 / 今月の平均達成率 (scheduledCount > 0 の日のみ平均)。
- 各習慣のミニ草 (直近 8 週間) を行内に表示。今日マーカー付き。タップで詳細へ遷移。
- HabitDetailView: 直近のヒートマップ + 履歴 (予定日だけ編集可) + 現在/最高ストリークと合計達成数。既存習慣の編集導線あり。

### 4.7 記念日 (Anniversary / Countdown)
- 登録: タイトル / 日付 / 種別 (countdown/since) / 毎年繰り返し
- 表示: D-xxx / D-0 / +xxx

### 4.8 ヘルスケア
- データ: 歩数 / 睡眠 / Apple フィットネス (ムーブ・エクササイズ・スタンド) / 活動量
- 動作: 初回権限取得 → 許可済みのみ読み込み。Today: 当日データ、Health タブ: 週・月・半年・年グラフ
- 歩数グラフ (棒、値ラベル付)・睡眠タイムライン (途切れない棒 + 時間表示)・相関チャート
- 履歴ビュー: 範囲 (週/1か月/6か月/1年) 切替 + 横スワイプ

### 4.9 設定 (Settings)
- カレンダー連携: 外部カレンダーとアプリ内カテゴリのマッピング設定
- プライバシー: アプリロック機能 (Face ID / Passcode / Touch ID)。バックグラウンド遷移時にロック、復帰時に認証要求。
- ヘルスケア: OS設定へのリンク案内
- サポート: アプリ内レビュー依頼 (条件付き自動トリガー + 手動ボタン)、開発者への問い合わせメール作成 (端末情報自動挿入)

### 4.10 大切な人への手紙 (Letter Sharing)
- 友達ペアリング (招待リンク / 友達リクエスト)、E2EE 暗号化手紙の送受信、配信条件 (固定日時 / ランダム / 最終ログイン)
- バックエンドは Firebase (Auth / Firestore / Storage / Cloud Functions)。ペアリング作成・配信判定はサーバーサイド
- 詳細仕様: `docs/letter-sharing-spec.md`、未来への手紙 (ローカル) は `docs/letter-to-future-spec.md`、iCloud 同期は `docs/letter-icloud-sync-spec.md`
- セキュリティ対応状況: `docs/security-audit-report.md`

### 4.11 ウィジェット / 壁紙カレンダー
- WidgetKit 拡張 (`LifelogWidgets/`): 予定 / 記念日 / メモ / 習慣の4種。App Group 経由で SwiftData ストアを共有
- 予定ウィジェットの中サイズ: 左に今日の予定・未完了タスク、右に当月のミニカレンダーを表示。今日を丸で強調し、予定のある日に点を付ける。日付タップでアプリの該当日を開く
- シミュレーターの表示確認: Debug + iOS Simulator で `-simulator-demo-data` を付けて起動すると、`group.lifelog.screenshots/simulator-demo.store` のみに予定・タスクと、振り返り地図用の全国約1,000地点の日記を投入する。地図サンプルは47都道府県に分布し、訪問回数1 / 3 / 6回、未タグ・単色・最大9色の例を含む。設定はシミュレーター内に保持し、日付タップやアイコンからの再起動でも同じデモを表示する。実機・Release は無効。通常ストアの移行・CloudKit・外部カレンダー/ヘルス取得・実アカウントの自動更新はデモ中に行わない
- デモを終了する場合はシミュレーターのアプリを終了し、`-simulator-demo-off` を付けて再起動する。通常ストアに戻り、デモデータ自体は専用ストアに残す
- 壁紙カレンダー: App Intents (`UpdateWallpaperCalendarIntent`) が利用者の背景写真・背景色・予定・表示設定から画像を生成し、ショートカットの標準アクションでロック画面に設定する。配布物に作成者の写真や端末固有の壁紙参照を固定しない
- 初回導入: ロック画面カレンダーをその端末で初めて開いたときだけ専用シートの「ようこそ」を自動表示し、「1 壁紙を作る → 2 ショートカットを追加 → 3 自動更新を設定 → 完了」へ進む。各画面は1つの目的に絞る。初回表示時に端末内へ表示済み状態を保存し、途中で閉じても次回は自動表示しない。通常の設定ページには背景・表示内容の編集と「設定手順をもう一度見る」を用意し、再表示も「ようこそ」から始める
- ステップ1は、背景写真／背景色の選択、レイアウトと表示する週数、表示する情報（プライバシー）、壁紙の完成プレビューの4画面に分ける。写真の位置や拡大率の調整は案内の上に別シートで開く。プレビュー画面では「この壁紙でよろしいですか？」と確認し、利用者が確かめてからステップ2へ進む
- ステップ2は、ショートカットを使う理由、追加、動作確認をそれぞれ別画面にする。画像は lifelify が作り、壁紙への反映には Apple のショートカットを使うことを説明する。`lifelog/Info.plist` の `WallpaperCalendarShortcutURL` から完成済みショートカットを追加し、初回の手動実行・必要な許可・対象壁紙と表示結果を端末上で確認する
- ステップ3はまず自動更新の目的を説明し、その後に5枚の手順画像を1画面ずつ表示する。lifelify を閉じたときにショートカットを再実行するパーソナルオートメーションを作成し、共有リンクだけでは自動更新が設定されないことを伝える。各画面で操作先・押す項目・アプリに戻るタイミング・確認内容を示し、「次へ」「戻る」で移動する。外部アプリから戻っても、そのシートを開いている間は現在のページを保つ。最後の確認画面で「設定を確認しました」を押すと、独立した「設定できました」画面へ進み、「閉じる」で終了する。完了表示は利用者の確認に基づき、導入状況の自動検証やインストール済み管理は行わない
- 手動作成は通常の設定ページ最下部と、導入シートのステップ2（ショートカット）の最下部に「※ 追加できない場合は、手動で作成できます。」の補助リンクとして置く。導入シートではショートカットの段階だけに表示する。リンク先に詳しい手順と生成画像の書き出しをまとめる。共有 URL が未設定・不正な場合も手動作成ガイドを開く。配布・実機検証・5言語対応の手順は `docs/wallpaper-shortcut-distribution.md` を参照

### 4.12 日記写真のiCloud保存
- 設定の「日記の写真とiCloud」に一括同期ボタンを置く。初回の手動開始後、新規写真と未完了の処理を起動・復帰時などに再試行する。
- 保存方法は「端末容量を節約」「すべて端末にも保持」の2択。節約時はアップロード成功と同期情報の保存後に高画質版を解放し、拡大中だけ取得する。未同期写真は解放しない。
- 全写真のサムネイルを端末に永続保存する。「今日の一枚」の切り替えと一覧表示は通信を待たずに行える。
- 日記から削除した写真は独立したクラウドコピーも削除する。オフライン時は削除待ちを永続化する。写真アプリには影響しない。
- 通常のiPhone移行で本文・写真ID・サムネイル・同期情報を引き継ぐ。新規インストールだけでの全文復元・複数端末の日記編集同期は今回の対象外。
- 詳細・CloudKitの配布設定・検証範囲は `docs/diary-photo-icloud-sync.md` を参照。

### 4.13 買い物リスト
- 下部タブの3番目に「買い物」を配置し、画面タイトルは「買い物リスト」とする。タブ順は ホーム / カレンダー / 買い物 / 習慣 / ヘルス。
- 購入先を「すべて」「未指定」または利用者が登録した購入先で絞り込む。「すべて」では購入先ごとに商品をまとめて表示する。
- 商品名だけで追加可能。メモは追加画面の「＋メモ」から任意に入力でき、商品の編集画面でも変更できる。数量の専用入力欄は設けず、数量もメモに記載する。数量欄の撤去に伴うデータモデルやスキーマの変更は行わず、既に保存されている数量の値を保持する。購入先未指定でも保存できる。
- 一覧の「商品を追加」から標準の大きなシートで専用の商品追加画面を開く。見出しと件数を「今回追加した商品（件数）」の1行にまとめ、今回追加した商品だけを商品名・購入先・メモとともに即時表示する。各商品の「取り消す」で今回の追加を取り消せる。上部の「閉じる」で購入先ごとにまとまった通常の一覧へ戻り、保存済みの商品は保持する。
- 専用画面の購入先は横スクロールできる選択肢として常時表示し、一覧メニューを開かずに切り替えられる。購入先と商品名の入力部分はタップしやすさを保ちながらコンパクトにまとめる。商品名はカプセル形の入力欄、追加は隣接する丸い「＋」ボタンとする。入力欄はキーボード直上に配置し、キーボードの上に別の「入力を完了」ツールバーや余白を挟まない。
- 商品を連続追加できる。追加するたびに商品名とメモを即時保存し、成功時だけ両方の入力を空にしてメモ欄を閉じる。保存失敗時は入力内容とメモ欄の表示を保持する。追加ボタンと商品名入力の Return のどちらでもキーボードと商品名の入力位置を維持する。メモ欄は画面内の標準の複数行入力とする。選択した購入先は次の入力にも引き継ぐ。特定の購入先を表示している場合は、その購入先を追加時の初期値にする。追加画面を閉じる操作は保存確定のためには不要とする。
- 「未指定」の選択肢は長押しメニューから非表示にでき、購入先の管理画面の「未指定を表示」で再表示できる。この表示設定を端末内に保存し、一覧上部のフィルタと専用の商品追加画面に反映する。非表示でも商品・購入履歴は保持し、「すべて」では未指定の商品を引き続き表示する。未指定を選択中に隠した場合、登録済み購入先があれば先頭を追加時の購入先にする。
- 商品行全体のタップで購入チェックを切り替え、習慣と同じアニメーション付きチェックボックスを使う。独立した行メニューから編集・削除などを行い、商品名のタップも購入チェックにする。チェック直後は約0.3秒のアニメーションを見せてから自動で購入済み一覧へ移し、手動の「購入済みを整理」は設けない。
- 購入チェック後は画面下部に「商品名を購入済みにしました」と「元に戻す」を6秒間重ねて表示する。一覧や「商品を追加」ボタンの位置は動かさない。連続チェックでは最後の1件に更新し、表示期限を延長する。「元に戻す」でその購入状態と購入回数を復元し、操作ミスを購入頻度に数えない。通知が消えた後も購入済み一覧の行をタップして「買うもの」に戻せる。
- 購入済みは折り畳める一覧にまとめ、繰り返し購入した回数の多い商品を上に置き、同数の場合は最近購入したものを上にする。購入済みの行をタップすると、同じ商品のID・商品名・数量・メモ・購入先・購入回数を保って「買うもの」に戻す。再度購入チェックした時に購入回数を加算する。行メニューには再追加する別操作を置かず、毎回コピーを生成しない。購入済みの下に「購入済みの商品をタップすると『買うもの』に戻せます。」を表示し、折り畳み中も案内を残す。過去に作成された同じ `familyID` の商品系列の頻度は引き続き集計する。同じ商品名を手入力しただけの商品は別に扱う。
- 商品の編集・削除と、購入先の追加・名前変更・削除・並べ替えに対応する。購入先は店舗名でも「スーパー」などの分類名でも利用できる。
- ローカルの SwiftData の `SDShoppingItem` / `SDShoppingPlace` に永続化する。購入頻度のため `ShoppingItem` / `SDShoppingItem` に `purchaseCount`（初期値0）と `familyID`（初期値nil）を追加し、既存の商品・購入履歴を移行後も保持する。`familyID` がnilの商品は自身のIDを系列の識別子として扱う。過去の商品コピーと頻度系列の互換性は維持し、既存の属性やデータは削除しない。他のエンティティの定義は変更しない。追加・変更・購入チェックを端末内へ即時保存し、失敗時は変更を取り消してエラーを表示する。購入先を削除しても商品・購入履歴は削除せず「未指定」に移す。オフラインでも利用でき、未購入は日付をまたいでも保持する。CloudKit による自動同期は行わない。
- HIG に沿った標準のナビゲーション・一覧・入力シートを使う。商品イラストや装飾画像は追加せず、操作を表すアイコンには SF Symbols を使う。
- UI とエラー表示を `ja` / `en` / `ko` / `zh-Hans` / `zh-Hant` で揃える。利用者が入力した商品名・購入先名・数量・メモは翻訳・上書きしない。

## 6. 非機能要件
- iOS 17+ 推奨 (SwiftUI 最新機能)
- 永続化: SwiftData (`Models/SwiftDataModels.swift` の `@Model` 群 + `Services/Persistence.swift`)。App Group 共有ストア。レガシー UserDefaults からの移行は `Services/MigrationManager.swift`
- パフォーマンス: Today 画面 1 秒以内ロード。HealthKit フェッチはバックグラウンドで UI ブロック禁止
- セキュリティ: 日記本文・管理データはローカル保存。日記写真は利用者が設定の一括同期を開始した場合のみ、本人のCloudKit private databaseへ独立したコピーを保存する。写真アプリの元写真は変更しない。詳細は `docs/diary-photo-icloud-sync.md`。手紙共有の認証・保存とは独立して扱う。
- プライバシー: HealthKit / Photos アクセス文言整備 (選択写真推奨)
