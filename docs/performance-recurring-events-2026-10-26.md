# 繰り返し予定・削除処理の軽量化

2026年10月26日。`docs/requirements.md` §4.2 の表示・削除範囲を維持し、予定の展開、週まとめ削除、通知の更新、削除画面の再描画を見直した。

## 変更内容

- 展開処理は毎日を走査せず、繰り返し規則に合う日・週へ進む。表示期間に入ることを確認してから発生回IDと通知日時を生成する。終了済みのシリーズも、表示期間内への振替がある場合は残す。
- ホーム・カレンダー・Widget・壁紙の共通クエリでは、重複排除後の整列を1回だけ行う。通知は表示順の整列を省き、通知時刻で整列する。
- 削除範囲の「この週」を表示できるかは、削除画面を要求したときだけ判定する。入力・シート作成・再描画では週の予定を展開しない。閉じて再び開くと最新状態で判定する。
- 7日分の週まとめ削除は、例外の取得・保存・公開更新と通知の再計画を各1回にまとめる。すでに同じ内容の例外がある場合は再公開・再計画を省き、未保存データの再試行は維持する。
- メモ・URLだけの編集では通知を再登録しない。元の開催回の確認も、周辺期間の展開を使わず直接取得する。
- 通知設定のないシリーズは通知用の18か月分の展開から外す。ただし、個別の開催回だけ通知を有効にした例外は対象に残す。

## 展開処理の比較

共有の展開処理を切り出したmacOS Release計測。変更前後を同一データで交互に実行し、9組のサンプルで各3回実行した1回あたりの中央値を比較した。通常の表示順の整列を含む。アプリ全体やiPhone実機の応答時間を示す値ではない。

| 条件 | 変更前 | 変更後 | 比率 |
| --- | ---: | ---: | ---: |
| 隔週・20年の表示範囲、522開催回 | 13.443 ms | 4.876 ms | 2.76倍 |
| 200シリーズ・複数タイムゾーン・1か月、600開催回 | 23.054 ms | 12.026 ms | 1.92倍 |
| 600シリーズ中400件が終了済み・1か月、600開催回 | 27.488 ms | 11.943 ms | 2.30倍 |

88種類の比較データで変更前後の出力が一致した。夏時間、午前1時に始まる日、サモアの欠落した暦日、間隔の大きい繰り返し、終日・複数日、期間外からの振替、終了日、安定IDを含む。

## 回帰テスト

- `EventRecurrencePerformanceTests`: 大きな間隔、遠い表示期間、欠落した暦日、直接取得、振替、整列と計測用のデータ。
- `CalendarRecurrenceMutationPerformanceTests`: 週まとめ削除の保存・公開回数、同じ内容の更新、保存再試行、複数の例外、重複した例外、URL・メモの変更。
- `CalendarRecurrenceReminderOptimizationTests`: メモ・URL編集時の通知維持、通知なしのシリーズ、個別通知の例外。
- 既存の繰り返し・削除・通知・移行・URL・各表示先のテストを引き続き使用する。
